# 管理员独立入口与强凭据方案

## 用户已确认的最终方案

采用 Nginx 转发独立后台地址，复用现有应用服务；管理员账号和密码使用高强度随机值。

## 入口与认证

- 主系统继续通过根路径访问；后台入口为 `/admin`。
- Nginx 使用独立 Basic Auth 账号密码保护 `/admin`、`/admin/`、`/admin/approvals` 和 `/api/admin/`。
- 账号为 `mgr_` 加 16 位随机十六进制字符；密码为 32 位随机字符，包含大小写字母、数字和符号。
- 服务器保存密码哈希，浏览器代码不保存管理员密码或代理密钥。
- Nginx 认证通过后向回环地址的应用注入私有代理密钥和已认证用户名。普通系统路径清空对应请求头。
- `ADMIN_PROXY_AUTH=1` 时，应用仅通过代理密钥授权管理接口，普通系统的管理员 Cookie 和 JSON 密钥字段不能绕过后台认证。
- 后台写请求携带专用请求头，以防浏览器缓存的 Basic Auth 被跨站表单利用；浏览器不能修改内部代理密钥。
- 后台账号认证后直接显示审批面板，无需再次输入管理密钥。

## 密码更新与部署

通过 SSH 在服务器上生成新凭据，更新 Nginx 密码哈希，并同步更换已有网站管理员的用户名和密码哈希。保留其他用户及业务数据。改动前备份数据库与 Nginx 配置；发布新代码后测试配置、切换版本、重载服务。

当前网站协议仍为 HTTP。认证验证只在服务器本机执行，公网仅检查未登录访问受到保护，不在公网发送管理员凭据。
