# Skills Manager 功能与页面优化方案

## 一、感知 —— 当前问题诊断

### 1.1 当前功能清单（10 个标签页）

| # | 标签 | 类型 | 核心功能 |
|---|------|------|----------|
| 1 | 📋 本地 Skills | 浏览 | 展示全部 388 个 Skills，分页浏览 |
| 2 | 🐙 GitHub 仓库 | 搜索 | 搜索 GitHub 开源仓库 |
| 3 | 🎯 场景推荐 | 推荐 | 按场景（写代码/做测试/管项目...）推荐 Skill 组合 |
| 4 | 📂 分类浏览 | 浏览 | 按 15 个分类查看 Skills |
| 5 | 📦 打包清单 | 工具 | 购物车，选中后打包下载 |
| 6 | 🔍 发现新 Skills | 管理 | 从 GitHub 关键词/AI 发现新 Skills，审批入库 |
| 7 | 📅 版本发布 | 信息 | 查看 Skills 版本更新记录 |
| 8 | 👤 导入 Skill | 管理 | 手动创建或从 GitHub 导入 Skill |
| 9 | 🔄 自动更新 | 管理 | 运行发现→扫描→清理→索引全流程 |
| 10 | 🤖 AI 设置 | 配置 | 配置 AI API Key、模型参数 |

### 1.2 核心问题

**A. 导航过度膨胀（10 个平级标签）**
- 用户认知负担重，一眼找不到核心功能
- "浏览" 和 "搜索" 被拆成 3 个标签（本地 Skills、GitHub 仓库、发现新 Skills）
- 管理类标签（自动更新、AI 设置、导入、版本发布）与用户类标签混杂在一起
- 移动端 10 个标签横向滚动体验差

**B. 功能重叠与定位模糊**
- Hero 区的搜索框 + "全网"按钮 → 与 "GitHub 仓库" 标签功能重叠
- "本地 Skills" 标签（浏览全部）→ 与 "分类浏览" 标签功能重叠
- "发现新 Skills" 标签（GitHub 发现）→ 与 "GitHub 仓库" 标签功能重叠
- "自动更新" 标签（运行发现→扫描→索引）→ 与 "发现新 Skills" 部分重叠

**C. 信息架构不合理**
- 用户最常用的操作是"浏览 + 搜索 + 加入购物车"，但购物车是独立标签页，加入后看不到列表
- "AI 设置" 是配置项，用户设置一次后几乎不再访问，不应该是顶级标签
- "版本发布" 是静态信息展示，不需要独立标签
- 搜索框在最上方，搜索结果却跳转到"本地 Skills"标签，视觉流断裂

**D. 用户心智模型不匹配**
- 用户期望：搜索 → 浏览结果 → 看详情 → 加入清单 → 打包下载
- 当前流程：搜索 → 跳转到标签页 → 在标签页里看结果 → 切到另一个标签看购物车

### 1.3 改进方向

将 10 个标签重构为 **3 个核心区 + 1 个管理入口**：

```
主界面（始终可见）
├── 🔍 搜索栏（全局，始终在顶部）
├── 📋 浏览 Skills（默认视图，融合分类筛选 + 排序）
├── 🎯 场景推荐（保留，增强）
├── 📦 打包清单（改为侧边栏/底部抽屉，始终可访问）
└── ⚙️ 管理（折叠菜单，收纳：发现/更新/导入/发布/AI 设置）
```

## 二、规划 —— 具体改动方案

### 2.1 导航重构

**旧：10 个平级标签**
```
📋本地 🐙GitHub 🎯场景 📂分类 📦清单 🔍发现 📅发布 👤导入 🔄更新 🤖AI
```

**新：3 个主标签 + 1 个管理入口**
```
📋 浏览 Skills  |  🎯 场景推荐  |                          📦 清单(N)  ⚙️
```

- "浏览 Skills"：合并原来的"本地 Skills" + "分类浏览" + "GitHub 仓库"（GitHub 结果作为搜索的一种来源）
- "场景推荐"：保持不变
- "📦 清单(N)"：改为右侧固定按钮/面板，点击展开侧边栏，不离开当前页面
- "⚙️"：管理入口，下拉菜单包含：发现新 Skills、自动更新、导入 Skill、版本发布、AI 设置

### 2.2 浏览页重构

**当前问题：** 搜索框在 Hero 区，搜索结果在标签页内，搜索和浏览是分离的。

**新方案：**
- 搜索框始终在页面顶部（Hero 区下方），输入即搜索，实时过滤
- 搜索框左侧增加"来源切换"：本地 Skills | GitHub
- 分类筛选改为横向标签条（在搜索框下方），点击即过滤
- 移除 "分类浏览" 独立标签，功能合并到浏览页的分类筛选
- 移除 "GitHub 仓库" 独立标签，功能合并到搜索的来源切换

### 2.3 购物车改为侧边栏

**当前问题：** 购物车是独立标签页，加入后需切换标签才能看到清单。

**新方案：**
- 页面右侧固定一个"📦 清单(N)"按钮
- 点击展开侧边栏面板，显示购物车内容
- 在侧边栏中可直接操作（移除、打包下载、清空）
- 不离开当前浏览/搜索上下文

### 2.4 管理功能收纳

**当前问题：** 5 个管理/配置类标签占据导航栏。

**新方案：**
- 导航栏右侧增加 "⚙️ 管理" 按钮
- 点击展开下拉菜单：
  - 🔍 发现新 Skills
  - 🔄 自动更新
  - 👤 导入 Skill
  - 📅 版本发布
  - 🤖 AI 设置
- 点击菜单项打开对应模态框或跳转到管理面板（单页内切换）

### 2.5 去掉冗余功能

- **"全网"按钮**：移除，改为搜索框的"来源切换"（本地 / GitHub）
- **"版本发布"**：保留但收纳到管理菜单，数据从 GitHub Releases API 获取
- **"AI 设置"**：保留但收纳到管理菜单，改为模态框形式

## 三、执行 —— 实施步骤

### 步骤 1：HTML 结构重构（导航栏 + 布局）
- 缩减标签为 3 个主标签
- 新增右侧购物车按钮 + 管理下拉菜单
- 新增购物车侧边栏 HTML

### 步骤 2：浏览页整合
- 搜索框移到 Hero 下方，始终可见
- 增加来源切换（本地/GitHub）
- 增加分类筛选横向标签条
- 合并 `renderSkillsPage` 和 GitHub 搜索逻辑

### 步骤 3：购物车侧边栏
- 实现侧边栏滑入/滑出动画
- 购物车操作在侧边栏内完成
- 加入/移除时更新侧边栏内容和按钮状态

### 步骤 4：管理菜单
- 实现下拉菜单
- 原管理类标签改为模态框或内嵌面板
- 保留所有原有功能逻辑

### 步骤 5：移动端适配
- 标签栏在移动端横向滚动
- 侧边栏在移动端改为底部抽屉
- 管理菜单在移动端适配

- Skill 卡片组件、详情页、场景推荐逻辑
- i18n 多语言框架
- 购物车 localStorage 逻辑
