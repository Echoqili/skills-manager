# Skills Manager 项目经验总结（Lessons Learned）

> 沉淀本轮迭代中的关键经验、踩坑记录与最佳实践，供后续开发参考。

---

## 1. 不要让随机数据“假装”真实数据

### 现象
Skill 卡片和详情页的 `downloads / rating / rating_count` 在数据缺失时使用 `Math.random()` 生成，导致同一 Skill 每次刷新数值都不同。

### 影响
- 用户对数据真实性产生怀疑
- QA 测试难以验证统计展示是否正确
- 每次渲染结果不一致，增加调试难度

### 经验
- **缺失数据宁可留空或隐藏，也不要伪造。** 真实产品的数据可信度比“看起来丰富”更重要。
- 若需要占位，统一使用 “—” 或隐藏整个统计区块，并在数据源侧补充真实字段。

---

## 2. 后端接口字段必须满足前端多语言需求

### 现象
`/api/skill/<name>` 最初只返回 `name` 和 `description`，前端详情页在中文环境下只能显示英文 id。

### 影响
- 中文用户看到的标题是 `acceptance-driven-planner` 这类英文 id
- 描述为空或回退到英文，国际化体验断裂

### 经验
- 设计 API 时，**多语言字段应一次性返回完整集合**（如 `name_zh / name_en / description_zh / description_en`），让前端只负责选择展示语言。
- 前端回退链要明确：`当前语言字段 -> 通用描述 -> 英文名`，避免直接回退到 id。

---

## 3. DOM 元素顺序会影响脚本执行

### 现象
自定义确认对话框 HTML 被放在 `<script>` 之后，脚本执行时 `document.getElementById('confirmOk')` 返回 `null`，`addEventListener` 报错，导致整个 `init()` 流程中断，`loadStats()` 未被调用。

### 影响
- 页面统计条和 Skill 卡片全部空白
- 部署到 Render 后功能直接不可用

### 经验
- **脚本依赖的 DOM 元素必须出现在脚本执行之前**，或者将脚本放到 `DOMContentLoaded` / 页面底部执行。
- 对 `getElementById` 的结果做 null 安全检查，避免单点报错阻塞整个初始化流程。

---

## 4. 状态变化后必须同步所有相关 UI

### 现象
加入购物车后，购物车计数徽标更新了，但 Skill 卡片上的按钮仍显示“加入清单”。

### 影响
- 用户不确定操作是否生效
- 同一 Skill 在列表页和详情页状态不一致

### 经验
- 任何全局状态变更后，**应通过一个统一的同步函数刷新所有依赖该状态的 UI**。
- 给可更新的 UI 元素打上稳定标识（如 `data-skill-name`），避免依赖动态生成的 id。

---

## 5. i18n 占位符必须跨语言保持一致结构

### 现象
中文页脚文案包含 `<span id="footerTotal">0</span>`，而英文文案只写 `{}`，导致切换语言后 `footerTotal` 更新逻辑失效，页脚显示 `Skills Manager | {} Skills | ...`。

### 影响
- 英文模式下出现未替换的占位符，显得产品粗糙

### 经验
- **所有语言的同一 i18n 键应保持相同的 HTML 结构和占位符**，只是在文字上做翻译。
- 若需要动态替换数字，确保替换目标（如 `#footerTotal`）在所有语言模板中都存在。

---

## 6. 自动化测试是发现体验问题的有效手段

### 现象
通过 Playwright MCP 对站点进行全量点击测试，才系统性地发现了 12 处问题，包括随机数据、空描述、购物车状态、页脚占位符等。

### 经验
- 功能能跑通不等于体验没问题，**全链路点击测试能暴露很多“看起来正常”的细节缺陷**。
- 测试应覆盖：初始加载、搜索、筛选、分页、详情、购物车、语言切换、错误边界等。
- 建议将核心交互的回归测试固化成脚本，避免后续迭代回退。

---

## 7. 数据质量会直接影响前端展示效果

### 现象
即使后端接口返回了 `description_zh`，仍有大量 Skill 的 `description` 字段是英文 id 或 `description_zh` 为空，导致卡片/详情描述显示不理想。

### 经验
- 前端展示问题有时根源在数据。**建立数据清洗和校验流程**，确保关键字段（name、description、category）在录入时就符合规范。
- 对于历史数据，可批量补充或生成多语言描述。

---

## 8. 部署配置要尽早纳入版本控制

### 现象
Render 部署所需的 `render.yaml` 和 `Procfile` 是后期才创建的。

### 经验
- **部署配置应与代码一起管理**，避免“本地能跑、线上不行”的环境差异。
- 在 README 中补充部署说明，方便新成员或 CI/CD 流程使用。
