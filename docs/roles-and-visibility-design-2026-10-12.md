# 角色、功能权限与入口显示设计

## 目标

保留现有 Nginx 独立后台入口，增加超级管理员、管理员账户管理及无权限功能隐藏。保留已有账号、技能和业务数据。

## 角色规则

- 普通用户：只能使用分配的业务功能。
- 管理员：可以审批普通账号、管理普通用户的功能权限；业务功能仍遵守分配的权限。不能创建、晋升、降级或修改其他管理员。
- 超级管理员：拥有全部功能权限，并独占管理员账户管理能力。
- 超级管理员初始化用户名为 `superAdmin`，密码使用用户指定的初始化值，仅在首次初始化创建；首次登录必须更换密码，完成前不能执行管理操作。部署更新不重置已有超级管理员密码。
- 超级管理员自身不能被普通管理员降级、禁用或改权；不得禁用或降级最后一个超级管理员。

## 页面与操作

- 普通系统继续使用 `/`；管理员后台继续使用 `/admin`。
- 超级管理员使用独立页面 `/super-admin` 管理管理员账户，包含账号列表、将普通账号晋升为管理员、将管理员降级为普通用户、启用或禁用管理员、重置管理员密码。
- 普通管理员的账户列表仅提供普通用户管理操作；管理员账户管理不混入该页面。
- 现有“分配权限”弹窗增加“隐藏无权限功能”选项，账号列表提供对应的一键设置按钮。
- 普通系统也提供“一键隐藏无权限功能”按钮，切换后保存该账号的显示偏好；隐藏只影响展示，不替代后端权限检查。
- 无权限功能在显示状态下禁用并解释原因，隐藏状态下从导航、管理菜单和对应操作按钮中移除；当前页失去权限时返回可用页面。

## 权限与认证

- `[]` 明确表示无权限，`['*']` 明确表示全部权限，移除“空权限自动变成全部权限”的逻辑。
- 业务 API 检查真实角色与功能权限；普通管理员不能通过直接调用接口管理管理员或超级管理员。
- Nginx 改为从账号数据库动态验证后台账号，保证普通账号晋升后使用原有账号密码登录，降级或禁用后立刻失去相应后台入口权限。
- 管理员与超级管理员入口分别校验角色，继续使用已有 80 端口与回环应用服务。内部认证接口只供 Nginx 使用，公网不可直接调用。
- 后台写请求继续进行请求来源验证和权限检查，操作记录真实账号。

## 验证与部署

先覆盖角色越权、空权限、管理员晋升降级、禁用、初始密码限制和隐藏设置的回归测试，再修改实现。使用真实浏览器验证权限弹窗、两类后台页面与普通用户隐藏按钮。

部署前备份 SQLite 数据库和 Nginx 配置，迁移新增字段而不删除数据，保留现有复杂管理员账号。超级管理员默认密码仅用于初始化，修改后不能在后续部署中被覆盖。

当前网站使用 HTTP，发送真实管理员密码的自动验证仍只在服务器本机执行。公网仅做无凭据的访问控制检查。
